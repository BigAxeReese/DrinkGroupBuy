### 2.2.3 功能性需求

顧客與商家皆使用 Google 帳號登入。Firebase Authentication 負責驗證登入身分，Node.js API 再依 PostgreSQL 中的角色與店家關聯資料判斷顧客或商家權限。顧客只能操作自己的訂單、付款與取餐資料；商家只能操作自己的菜單、活動、活動訂單、製作與核銷資料。


## 功能一：顧客瀏覽與選擇團購功能

顧客打開 App 後，可以使用 Google 帳號登入。顧客登入完成後，進入顧客系統首頁。顧客依提示授權定位，提供所在座標。顧客可依所在位置，查看地圖或列表中附近店家與活動。顧客可拖曳、縮放地圖或設定篩選條件，查看不同條件的店家及活動。顧客可點擊想加入的團購活動，並且查看店家名稱、優惠門檻、目前杯數、剩餘時間、活動狀態與取餐時間；等活動詳細資訊。顧客確認參與後，可以進入店家菜單頁面。


### 主要流程

顧客打開 App。

顧客使用 Google 帳號登入。

顧客進入顧客首頁。

顧客授權定位。

顧客查看附近店家與招募中的團購活動。

顧客透過地圖或列表瀏覽活動。

顧客拖曳、縮放地圖或設定篩選條件。

顧客點選想加入的團購活動。

顧客查看活動詳細資訊。

顧客確認欲參與後進入店家菜單頁面。


## 功能二：顧客點餐與購物車功能

顧客進入店家菜單介面後，可以瀏覽飲品品項、分類、說明與價格。顧客可以選擇飲品，設定甜度、冰塊、加料與數量，再加入購物車。顧客可以繼續選購飲品，也可以查看購物車明細、品項小計、訂單總額與團購進度。顧客在送出訂單前，可以修改訂單、刪除品項或退出團購，並需選擇是否接受未達優惠時以原價購買。顧客確認訂單無誤後即可送出訂單，正式加入團購。


### 主要流程

顧客進入店家菜單介面。

顧客瀏覽飲品品項、分類、說明與價格。

顧客點選飲品。

顧客設定甜度、冰塊、加料與數量。

顧客將飲品加入購物車。

顧客繼續選購其他飲品或進入購物車頁面。

顧客查看購物車明細與團購進度。

顧客修改訂單內容。

顧客選擇是否接受未達優惠時以原價購買。

顧客確認無誤後送出訂單。


## 功能三：顧客訂單、付款與取餐功能

顧客送出訂單後，依照引導前往 LINE Pay Sandbox 預授權流程。顧客完成預授權後，回到 App 查看付款狀態，也可以查看進行中訂單、團購進度。預授權成功後，訂單成立並納入活動統計。顧客可於團購時間截止前 30 分鐘以前修改訂單或退出團購。顧客參與活動達標並完成付款後，即可取得取餐代碼，依取餐時間到店取餐；顧客完成取餐後，該筆團購訂單移至歷史紀錄。


### 主要流程

顧客送出訂單。

顧客前往 LINE Pay Sandbox 預授權流程。

顧客完成預授權後回到 App。

顧客查看付款狀態。

顧客查看進行中訂單、團購進度。

顧客於允許時間內可修改訂單或退出團購。

顧客所參與團購活動達標。

顧客完成付款。

顧客獲得取餐代碼。

顧客依取餐時間到店出示取餐代碼取餐。

顧客完成取餐後，訂單進入歷史紀錄。


### 顧客修改訂單副流程

顧客進入我的訂單。

顧客選擇欲修改的團購訂單。

顧客於截止前 30 分鐘以前可修改飲品、數量或客製化選項。

若已進入截止前 30 分鐘，顧客不可修改訂單。

顧客確認修改內容。

顧客查看修改後結果。


### 顧客退出團購副流程

顧客進入我的訂單。

顧客選擇欲退出的團購訂單。

顧客於截止前 30 分鐘以前可退出團購。

若已進入截止前 30 分鐘，顧客不可退出團購。

顧客確認退出。

顧客查看退出結果。


> 補充規則｜商家建立活動時必須設定取餐時間，顧客加入前可以查看。活動達標並完成請款後，系統產生取餐代碼。代碼自取餐開始時間起保留 3 小時；若商家當日營業結束早於 3 小時，則保留至當日營業結束；24 小時營業商家仍保留 3 小時。顧客應於有效期間內到店出示代碼，商家核對後交付飲品並更新為已取餐。代碼到期後，訂單結束並移至歷史訂單，且不自動退款。逾期後若飲品仍在且商家判斷可安全交付，顧客可憑歷史訂單協調領取；若因品質、衛生、保存時間或條件不適合交付，商家可以不再提供原飲品，且不得交付變質、腐敗、疑似污染或有食品安全疑慮的飲品。商家保管期間仍應依飲品特性合理冷藏、保溫或避免污染。若因商家保存不當、製作錯誤或其他可歸責於商家的原因無法交付，應另依退款、重做或補償流程處理，不得視為顧客逾期；顧客在有效期間內到店而商家無法交付時，也不得標記為逾期未取。以上逾期未取規則必須在顧客送出訂單前清楚顯示。


## 功能四：商家菜單與團購活動建置功能

商家打開APP後，可使用Google帳號登入。商家登入後即進入商家端預設主頁。商家可在主頁中查看進行中的活動、訂單數量、收款狀態與活動狀態。商家可以進入菜單管理介面，修改飲品名稱、價格、甜度、冰塊、加料與是否開放販售。商家可以建立團購活動，設定活動名稱、截止時間、取餐時間、最低成團數量、優惠杯數門檻、折扣規則、適用飲品與備註。商家發布團購活動後，活動狀態改為招募中並顯示於顧客端地圖或列表，商家可查看活動發布狀態。


### 主要流程

商家打開 App。

商家使用 Google 帳號登入。

商家進入商家端預設主頁。

商家查看進行中的活動、訂單數量、收款狀態與活動狀態。

商家進入菜單管理介面。

商家視需要修改菜單內容。

商家點選建立團購活動並設定團購名稱。

商家設定截止時間與取餐時間。

商家設定最低成團數量。

商家設定優惠杯數門檻與折扣規則。

商家選擇適用飲品並填寫活動備註。

商家發布團購。

商家查看活動是否成功發布。


### 商家修改菜單副流程

商家進入菜單管理。

商家選擇要修改的飲品或品項。

商家修改飲品名稱、價格、甜度、冰塊、加料或是否開放販售。

商家確認修改內容。

商家儲存菜單變更。

商家回到建立團購流程。


## 功能五：商家團購訂單與取餐管理功能

商家可以查看進行中的團購活動狀態。商家可查看團購累積杯數、訂單內容、收款狀態與達標情形。顧客完成預授權後，訂單會納入活動統計並加入製作清單，在活動達標後，商家可以查看製作清單並依訂單內容開始製作飲品。商家製作完成後標記可取餐。顧客到店取餐時，商家應核對取餐代碼，再標記取餐完成。商家若需取消已發布活動，必須在截止前 30 分鐘以前操作並填寫原因；進入截止前 30 分鐘後不可取消。活動結束後，商家可以查看結算結果。


### 主要流程

商家查看目前進行中的團購活動狀態。

商家查看累積杯數、訂單內容、收款狀態與達標情形。

商家查看製作清單。

商家依訂單內容準備製作飲品。

商家於活動達標後開始製作飲品。

商家製作完成後標記可取餐。

商家於顧客到店時核對取餐代碼。

商家標記取餐完成。

商家查看活動是否已完成。

商家查看結算結果。


### 商家取消團購副流程

商家進入已發布的團購活動。

商家點選取消團購。

商家於截止前 30 分鐘以前可取消團購。

若已進入截止前 30 分鐘，商家不可取消團購。

商家填寫或選擇取消原因。

商家確認取消。

商家查看取消結果。


> 補充規則｜商家應依功能三所列取餐代碼有效期間、逾期未取、食品安全、合理保存與可歸責事由處理取餐。核銷時應驗證代碼有效性與訂單歸屬，避免重複核銷；若涉及取消預授權、退款、重做或補償，應保留處理狀態與原因紀錄。

| 品質面向 | 需求說明 |
| --- | --- |
| 可用性 | 尖峰時段仍可支援顧客瀏覽地圖、點餐、付款預授權，以及商家查看訂單與製作清單。重要操作需避免重複送出，活動杯數與訂單狀態應維持一致。 |

| 安全性 | 登入採 Google OAuth 與 Firebase Authentication，不自行儲存密碼。角色僅分顧客與商家；顧客只能操作自己的訂單，商家只能操作自己的菜單、團購活動與相關訂單。API 應驗證身分權杖、角色與資源歸屬，並採 HTTPS 傳輸。 |
| 相容性 | React Native／Expo App 需支援主流 Android 與 iOS 裝置，並於不同螢幕尺寸與行動網路、Wi-Fi 環境中測試地圖、登入與付款回跳流程。 |
| 易用性 | 顧客端以地圖、列表、菜單、購物車與訂單狀態為主；商家端以菜單管理、建立活動、製作清單與核銷取餐為主。重要門檻、截止時間、取餐時間與逾期規則需於決策前清楚呈現。 |
| 擴充性 | 未來可增加商家自行註冊審核、正式金流、會員點數、推薦系統與活動成效分析。Node.js API 與 PostgreSQL 資料模型應採模組化設計，便於新增服務與報表。 |
