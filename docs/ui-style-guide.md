# UI 視覺風格指南

最後更新：2026-09-24

## 決定

- 風格方向：**紫青**（2026-09-24，使用者從配色網站挑了一組四色，取代先前的「奶茶上色」黑糖褐）。四色各有分工：深紫 `#321E48`＝文字與連結、灰藍 `#43637E`＝按鈕與畫出來的線、青 `#65DCD5`＝裝飾外框與「進行中」標籤底、薄荷 `#D9FFF4`＝色塊底。
- 舊規則「App 內不使用藍色」（2026-09-20 使用者比較四組藍色後選定黑糖褐）已隨新配色作廢：灰藍是新主色。桌面圖示（`mobile/assets/icon.png`）與登入插圖（`mobile/assets/login-hero.png`）仍是舊的鈷藍，比新配色鮮豔，待重新上色。
- 第一版**不新增任何套件**：只用 React Native 內建元件與系統字型；底部導覽用「圓點＋文字」，小圖形用 View 拼。
- 已套用到**顧客端全部 10 個畫面**（首頁、即時地圖、店家菜單、店家的團購列表、團購詳情、團購進度、選飲料、購物車、付款預授權、我的訂單、個人中心、取貨資訊）；**登入選角色與商家端的 6 個畫面也已改用同一套設定值**（這幾個只換顏色，版面與按鈕形狀維持原樣，按鈕待重做；商家首頁原本的藍色滿版橫幅改成一般的店名列加薄荷底統計卡）。全部 19 個路由都在 `milkTeaRoutes.js` 清單裡，共用元件的舊樣式分支已沒有畫面在用，可以清理（見「導入順序」第 5 項）。

數值（色碼、字級、圓角）以 [`mobile/src/theme/tokens.js`](../mobile/src/theme/tokens.js) 與 [`statusTones.js`](../mobile/src/theme/statusTones.js) 為準；[`mobile/tests/themeTokens.test.mjs`](../mobile/tests/themeTokens.test.mjs) 會自動檢查對比度與狀態對照。本文件只說規則與原因。

## 原則

1. **每一種顏色只管一件事。**
2. **全 App 只有 2px 一種線粗。** 實心灰藍＝可以按；白底加 2px 灰藍外框＝畫出來的線稿，或「目前被選中」的東西。
3. **整個 App 是平的**：不用陰影、漸層、濾鏡。只有蓋在畫面上方的東西（底部彈窗、提示條）用 Android 原生的浮起效果（elevation）。
4. **中文字只用一般（400）與粗體（700）兩種粗細。** 各家手機的中文字型不同，其他粗細不保證有效；層次靠字級、顏色、留白。
5. **意思不只靠顏色。** 每個狀態標籤都有文字，再加一個小記號：勾＝成功、三點＝進行中、驚嘆號＝留意、叉＝失敗、短橫線＝已結束。
6. **大字要設上限。** 取餐碼、珍珠數字、標籤加 `maxFontSizeMultiplier`（1.1），避免使用者調大系統字體時版面爆掉；固定高度一律改 `minHeight`。

## 顏色

對比度＝兩個顏色看起來差多少。文字要 ≥ 4.5，畫出來的線要 ≥ 3。

| 名稱（設定值名稱） | 色碼 | 用途 | 對比度 |
| --- | --- | --- | --- |
| 白（`page`） | `#FFFFFF` | 頁面與卡片的底 | — |
| 薄荷（`recess`） | `#D9FFF4` | 凹槽：珍珠盤底板、未選的標籤、頭像、次要面板 | — |
| 深紫（`text`） | `#321E48` | 主要文字、實心珍珠、取餐碼面板 | 白底 14.84、薄荷底 13.82 |
| 灰藍（`textSecondary`） | `#43637E` | 次要文字（只放白底或薄荷底） | 6.32／5.88 |
| 灰藍（`accent`） | `#43637E` | 可以按的實心底（配白字）、2px 畫出來的線 | 白字 6.32；線：白底 6.32、薄荷底 5.88 |
| 深紫（`accentInk`） | `#321E48` | 連結、被選中的標籤文字 | 14.84／13.82 |
| 薄荷（`onDark`） | `#D9FFF4` | 取餐碼面板上的字 | 13.82 |
| 輸入框線（`lineInput`） | `#728DA2` | 未選取的輸入框外框 | 白底 3.47 |
| 裝飾線（`lineDecor`、`lineRow`） | 青 `#65DCD5`、`#BFD0DB` | 顧客卡片外框、列與列之間的 1px 線；純裝飾，不承載意思 | 1.65、1.6（不要求；**青色不可用來畫有意義的線**） |

## 狀態標籤

| 色調 | 底／字 | 記號 | 用在 |
| --- | --- | --- | --- |
| 進行中（青，`info`） | `#65DCD5`／`#321E48` | 三點 | 招募中、訂單製作中、**訂單成立（已授權、還沒扣款）** |
| 成功／已鎖定（淡綠，`success`） | `#D2EFB8`／`#1F4A12` | 勾 | 已成團、可取餐、**已付款** |
| 留意（淡黃，`warning`） | `#FFEBB0`／`#6B4200` | 驚嘆號 | 已額滿、待付款、待審核 |
| 失敗（粉紅，`danger`） | `#FBD5DE`／`#9E1F3A` | 叉 | 流團、扣款失敗、已逾期、已駁回 |
| 已結束（冷灰，`neutral`） | `#E4E8EE`／`#3F4855` | 短橫線 | 已完成、已取消、已退款 |
| 預估（淡紫，`estimate`） | `#E4D6F6`／`#4B2A7A` | 三點 | 尚未達標、還會變動的折扣；結算後換成淡綠 |

33 種狀態的完整對照在 `statusTones.js`。**「訂單成立」（只預留額度）與「已付款」（真的扣了）不可以用同一種色調**，有測試守著。

## 字級與形狀

- 字級（px，字／行高）：珍珠數字 32／36、取餐碼 52／60、頁面標題 24／32、區塊標題 17／24、價格 18／24、按鈕 16／22、內文 15／23（商家密集畫面 14／20）、標籤 12／16、說明 12／17。
- 圓角：8（標籤內小塊）、14（輸入框）、20（商家卡片）、28（顧客卡片、珍珠盤、取餐面板）、999（按鈕、狀態標籤、珍珠）。按鈕高 52、圓角 26；可點的東西高度至少 44。
- 間距以 4 為單位（4／8／12／16／20／24／32）。顧客畫面左右留 20、卡片內距 20；商家與其他密集畫面左右留 14 到 16、列高 56。

## 招牌元件：當級珍珠盤

- 一顆珍珠＝一杯。實心深紫＝已訂；2px 灰藍空圈＝還沒人訂的名額。級距很大時一顆代表多杯，旁邊的文字永遠寫精確杯數。
- 只畫「你現在這一級」。下方的級距階梯每級一列：預估用淡紫，結算鎖定後換淡綠。
- 填幾顆的規則（實作時寫成純函式並加測試）：0 杯＝0 顆；達到級距＝全滿；其餘取「無條件捨去、至少 1 顆、最多留 1 個空位」，避免 99／100 杯看起來已經滿了。
- 用在：團購詳情與進度（大盤加階梯）、首頁卡片（迷你 5 顆）、取餐憑證（領幾杯就幾顆）、商家製作清單（杯數圓盤，維持唯讀）。

## 導入順序

採**逐畫面換皮**，新舊畫面暫時並存。做法：

- [`mobile/src/theme/milkTeaRoutes.js`](../mobile/src/theme/milkTeaRoutes.js) 列出已換新的畫面。外殼（`AppNavigator.js`）依這份清單為每個畫面**只決定一次**「新或舊」，透過 React context（[`MilkTeaContext.js`](../mobile/src/theme/MilkTeaContext.js)）通知共用元件，並回報給 `App.jsx`，讓狀態列與手勢列後面的底色也跟著換（新畫面白色、舊畫面維持淺灰藍 `#f6f8fb`）。
- 共用元件（`MobileScreen`／`Section`、`BottomNav`、`StatusBadge`、`DiscountSummaryCard`）讀取這個 context：在已換新的畫面裡自動變成新樣式，其他畫面預設是舊樣式，完全不受影響。已用修改前後的輸出逐字比對確認（23 個情境 0 個差異，另有 5 個「開啟新樣式」的對照組確實不同；比對用的腳本沒有存進專案，之後再改共用元件得重寫）。**畫面不需要、也不該手動傳旗標**，這樣不會有「忘了傳而悄悄退回舊樣式」的問題。
- 換一個畫面的步驟：把畫面裡寫死的色碼換成 `tokens.js`、把路由名稱加進清單（共用元件會自動跟著變）、在（網頁模擬或真的）畫面上逐一檢查。
- 全部畫面換完後：刪掉清單檔、`MilkTeaContext.js` 與各元件裡的舊樣式分支。

進度：

1. **（已完成）** 本文件、設定值、對比度測試。
2. **（已完成）第一批**：首頁（`NearbyGroupBuyActivitiesScreen`）、取貨資訊（`PickupInfoScreen`），以及「我的訂單」裡的取餐憑證區塊（共用元件 `PickupPass`）。新增小型珍珠進度（`PearlStrip`）與狀態標籤（`TonePill`、`StatusMark`）。首頁原本用負邊距做的滿版標頭已改成一般標題列。
3. **（已完成）第二批（2026-09-22）**：顧客其餘 9 個畫面（店家的團購列表、團購詳情、團購進度、店家菜單、選飲料、購物車、付款預授權、我的訂單本體、個人中心）與即時地圖（含網頁／原生兩版與篩選面板）。新增共用元件 `Card`／`Notice`／`ChoiceChip`／`CheckRow`／`QuantityStepper`／`EmptyPanel`／`ValueRow`／`PearlTray`（大型珍珠盤）／`TierLadder`（級距階梯），以及分頁切換滑動動畫（`ScreenTransition.jsx`，只用 React Native 內建 Animated，系統「移除動畫」設定會自動關閉滑動）。即時地圖的圖釘顏色（Android 原生水滴圖釘只能換色相，換皮時另外決定了非藍非紫的色相）與底圖（維持 Google 預設，見「不做的事」）是這一批的已知限制。付款預授權與我的訂單換皮後已依規定新增 `docs/AI-security-review-log.md` 一筆記錄（2026-09-22）；該筆也記錄了一項待決定的 UX 折衷（付款同步狀態目前仍是「非錯誤一律綠色」，未依實際狀態分色）。
4. **（已完成 2026-09-24）** 商家畫面（儀表板、開團、菜單、製作清單、退款、申請成為商家）與登入選角色畫面：只換顏色，寫死的色碼全部改成引用設定值；商家儀表板的負邊距滿版標頭改成一般標題列。用網頁預覽看過儀表板、開團、菜單管理、退款申請；**製作清單與有資料的儀表板（活動卡、歷史訂單明細）沒有實際看過**。
5. 全部換完後清理舊樣式（見上）。
6. 登入插圖重新上色成灰藍加青；桌面圖示與啟動畫面底色（`app.config.js`，原生設定，OTA 更新無法改）等下一次本來就要打包時一起換。

## 未決事項與已知風險

- 紫青配色是使用者從配色網站挑的四色，**沒有經過多方評審**，只做過對比度與色差計算（狀態標籤底色最小色差 15，門檻 8）。青色在白底上對比僅 1.65，只能當裝飾外框與標籤底。「進行中」標籤用青色，是所有標籤裡最亮的一顆，上實機後要確認是否太搶眼。
- 淡色標籤彼此色差偏小（最小 8.4，例如「失敗」粉紅與「已結束」冷灰），主要靠文字與記號分辨；上實機後要再確認。
- 付款文案是否把「授權」「請款」改成「預留額度」「扣款」：尚未決定，不在本次範圍。
- 導覽圖示：先用「圓點＋文字」。之後若要圖示，需新增套件，或自己畫透明底 PNG（現有兩張品牌 PNG 完全不透明，不能直接染色）。
- 登入插圖與桌面圖示仍是舊的鈷藍，比 App 內的灰藍鮮豔；登入插圖改用灰藍加青重新上色，桌面圖示等下一次打包。
- **顧客端全部畫面目前只在網頁模擬環境驗證過，Android 實機尚未確認。** 模擬用 `react-native-web` 把真正的元件畫成網頁再截圖，看得到排版與顏色，看不到 Android 的實際字型、字距、手勢與無障礙（TalkBack）表現。要在真機確認：取餐碼（52px、有字距）在窄螢幕與調大系統字體時不會爆版、各廠牌中文字型下的行距、導覽列圓點與標籤、即時地圖的圖釘顏色與原生彈出面板、分頁切換的滑動動畫。
- 同步提示（`ActivitySyncNotice`）已換皮（載入中改成安靜的說明文字、失敗改成 danger 色調提示框），沿用同一個共用元件，商家儀表板還是舊樣式。
- 換新與舊樣式的畫面之間切換時，會看到底色（白 vs 淺灰藍）與導覽列樣式的差異，這是逐畫面換皮期間的預期現象；目前只剩商家畫面與登入選角色會有這個現象。

## 設計預覽

[`docs/ui-style-previews/`](ui-style-previews/) 是選定風格前的比較稿，單一 HTML 檔、直接用瀏覽器開，只是網頁模擬，不是真的 App：

- `direction-A.html`：一筆珍珠（線稿延伸）。`direction-B.html`：杯貼取餐券。`direction-C.html`：奶茶上色，原本的深鈷藍版（這個藍已被否決）。三個是評審後的入圍方向。
- `blue-options.html`：同一個團購詳情畫面套 4 組藍色（深鈷藍、淺藍、霧藍、黑糖褐）。這是 2026-09-20 當時選定的黑糖褐（已於 2026-09-24 改定為紫青，這份預覽只留作決策紀錄）。

這些是決策紀錄，**不隨程式更新**；實際數值以 `tokens.js` 為準。

## 不做的事

- 暗色模式（專案目前只有淺色）。
- 新增套件，包含數字專用的圓頭字型（需要 `expo-font`）。
- 新功能：商家製作清單「逐杯打勾」、首頁「清單／地圖」切換。這次只換外觀。
- 地圖底圖（Google Maps 的水域、道路等圖磚）維持預設，不做客製樣式檔（2026-09-22 使用者決定）。因此即時地圖那一頁的底圖仍有藍色，這是「App 內不使用藍色」的唯一例外；蓋在地圖上的按鈕、標記、卡片、篩選面板仍照新樣式換。
